# Domain docs

This repo uses a single-context layout.

- Read the root `GLOSSARY.md` before exploring the codebase if the file exists.
- Read the decisions in `docs/adr/` that apply to the area you're working on.
- If either source is absent, continue with the task. Add glossary terms and decision records as they are resolved.

Use the glossary's terms in issue titles, refactor proposals, hypotheses, and test names. Flag gaps when an important term has yet to be defined.

If a proposal conflicts with an existing decision, cite the ADR and explain why the decision may need to be revisited.
